Live reload: re-render on `document-changed`, keep scroll by nearest heading, deleted-file notice

## Location
frontend + core

## Tests
`test_live_reload_after_save_updates_and_keeps_scroll` in `e2e/reload.spec.ts` — after an external write the change appears and scroll moves less than one screen

## Acceptance gate
Metric: `live_reload_ms <= 500` (from `status/plan.md`).

The core's share (write → debounced `document-changed`, ≤ 350 ms) is asserted in Rust; the
frontend's (event → re-rendered sheet with the reader's heading in place, ≤ 150 ms) in vitest.
Playwright is not set up yet, so the e2e test runs in jsdom with a fake layout.

```bash
set -euo pipefail
(cd src-tauri && cargo test test_save_by_rename_and_delete_emit_document_changed -- --nocapture)
npm exec -- vitest run src/ui/reload.test.ts --silent=false
```
